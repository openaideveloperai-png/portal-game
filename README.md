# TARE — The Kalden Ledger

A first-person puzzle game for the browser about weight, debt, and a village that was
drowned to fill a reservoir.

It is 1979. You are E. Lind, Auditor Third Class, sent to the State Institute of Ponderal
Measures inside the Kalden Dam. The dam's foundations report loads that cannot exist, and
forty-one thousand tonnes are missing from the Institute's ledgers. Your instrument, the
*tare*, can take weight out of a thing and put it into another. Weight is never destroyed,
only moved — and anything that owes weight falls *upward*.

- **Prologue**, three **Ledgers** of chambers (26 in all) and an **epilogue**
- Designed for roughly **1.5–2 hours** on a first playthrough (an estimate from the chamber
  count and puzzle length; it has not been timed with real players yet)
- Runs in a desktop browser with WebGL 2: recent Chrome, Edge, Firefox or Safari. Keyboard
  and mouse; there are no touch controls.

## Controls

| Input | Action |
|---|---|
| Mouse | Look |
| W A S D / arrow keys | Walk |
| Space | Jump |
| Left mouse | **Draw** one measure from what you aim at into the tare |
| Right mouse | **Give** one measure from the tare to what you aim at |
| E | Lift / put down, use, read |
| Q | Shove, or throw what you carry |
| Hold R | Restart the chamber |
| Tab | Journal (documents you have read) |
| Esc | Pause (settings, journal, restart, quit) |

If the page is embedded somewhere that won't capture the mouse, the game switches to
**drag to look, click to use** and says so. Opening it in its own tab restores normal mouse look.

Progress, settings and the documents you have read are saved in the browser
(`localStorage`). Chapters you have reached can be replayed from the title screen.
Settings include picture quality, field of view, mouse sensitivity, invert-Y, head bob,
subtitle size, and master, music and voice volumes.

## Running it

```bash
npm install
```

```bash
npm run dev
```

Then open http://localhost:5173.

To make a static build (relative paths, so it can be hosted from any folder):

```bash
npm run build
```

The result is in `dist/`. Any static file server works, for example:

```bash
npx vite preview
```

Some hosts refuse to serve `.glb` files. For those, build with the character models packed
into a script instead (`dist/assets/models.js`, loaded by the page before the game script):

```bash
npm run build:embedded
```

### Publishing on GitHub Pages

`.github/workflows/pages.yml` builds the game and publishes `dist/`. Turn it on once in the
repository's **Settings → Pages → Build and deployment → Source: GitHub Actions**, then run
**Deploy to GitHub Pages** from the **Actions** tab (it also runs on every push to `main`).

## How it is made

- **three.js** for rendering (filmic tone mapping, soft shadows, a small post stack with grain
  and vignette) and **Rapier** for physics, including a kinematic character controller.
- Every texture, sound effect, sign, poster and document — and the bells and music-box cues —
  is generated by the game's own code at load time. There are no texture or audio files.
- People are CC0 base meshes and motion-captured animation by Quaternius. Their clothes are
  painted onto each body on the GPU from an outfit description (shirt, waistcoat, coat, dress,
  apron…), with cloth geometry for coat tails and skirts.
- The photographs in the documents are small 3D scenes rendered once in the background and
  developed like 1940s prints.
- `DESIGN.md` covers the mechanics, the story, the level structure and the research on what
  makes games and interfaces read as machine-made, and what this one does instead.

### Source layout

| Folder | Contents |
|---|---|
| `src/core` | renderer, input, physics wrapper, procedural audio, saving |
| `src/render` | procedural materials and textures, geometry, props, signage, sky and water |
| `src/game` | the game loop, player, the tare, puzzle elements, characters, story, photographs |
| `src/levels` | prologue, the three ledgers, the epilogue, all documents |
| `src/ui` | title, HUD, subtitles, documents, menus (DOM + CSS) |
| `tools` | asset pipeline and the headless test harness |
| `public/assets` | characters, animations and fonts |

### Tests

`tools/shot.mjs` drives the game in headless Chromium through a debug API (`window.__tare`),
takes screenshots and reports console errors. The scenarios in `tools/scenarios` include
solvers that play every chamber to its exit (`solve-l1`, `solve-l2`, `solve-l3`). With the dev
server running:

```bash
node tools/shot.mjs tools/scenarios/solve-l1.mjs
```

Add `?nolock` to the URL (the harness does) to play without capturing the mouse.

### Rebuilding the character assets

The optimised files in `public/assets/models` are committed. To regenerate them from the
original Quaternius packs:

```bash
npm run assets -- <folder containing the Quaternius downloads>
```
